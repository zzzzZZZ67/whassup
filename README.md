# What's Up?

> AIE1101 · Vibe Coding 期末项目 —— 交互游戏（人机对战/人机协作：玩家动作 → 电脑物理世界响应）

用摄像头控制一个攀岩者：**你的头就是核心，你的左右手就是攀岩者的两只手**。握拳抓住岩点，张开手掌松手，靠交替抓握和荡跃，从地图底部一路爬到顶部。

**当前状态：v0.4.2 可运行（正式关卡 ×6 + 教学关 ×5 + 路段试玩 ×20）**。摄像头识别与浏览器表现尚未在真实设备上验证，文档会随实测更新，版本变化记在 [test.md](test.md)。

---

## 1. 三十秒上手

1. 双击项目根目录的 `index.html`（推荐 Chrome / Edge）。
2. 标题页选 **摄像头模式**（需要授权摄像头）或 **演示模式（无摄像头）**。
3. 摄像头模式：人退到摄像头前 1.5–2.5 米，让**头和两只手都在画面里**，站稳。
4. 按 `空格` 开始第 1 关（选完模式会自动开始，空格用于重新开始 / 过关后继续）。
5. 看着屏幕上的手，**握拳抓住平台边缘 → 把手往画面中心的黄点收（身体被拉上去）→ 张开手**；要上台面就先把身体绕到平台外侧升上去，再横着挪到台面上方松手。
6. 掉下去了就按 `R`，回到上一个检查点继续——不会失败，也不会卡死。

> 如果浏览器在"双击打开"时拒绝摄像头（Chrome 对 `file://` 的权限策略比较严格），请看第 9 节"摄像头打不开怎么办"，那里有两个不改主流程的兜底方案。

## 2. 运行环境

| 项目 | 要求 |
|---|---|
| 浏览器 | Chrome / Edge 最新版（需支持 WebAssembly 与 `getUserMedia`） |
| 摄像头 | 内置或外接 USB 摄像头均可，分辨率 ≥ 640×480 |
| 网络 | 首次加载需联网（姿态识别模型从 CDN 下载，之后浏览器会缓存） |
| 屏幕 | 建议 1280×720 以上；游戏画布按 16:9 等比缩放 |
| 安装 | 不需要。没有构建步骤、没有 npm、没有后端 |

**建议的游玩环境**：光线均匀（避免背光）、背景不要和衣服同色、摄像头略低于眼睛、手机/相机视野能同时容下头和手。

## 3. 操作方式

### 3.1 手势（主操作，必须使用摄像头）

| 手势 | 作用 | 说明 |
|---|---|---|
| 张开手掌 | 松手 / 保持自由 | 手的默认状态。此时手跟着你的真手移动 |
| 握拳 | 抓取 | 只有**在可抓取范围内**且**手在判定范围内**时才会真的抓住 |
| 抓取中握拳 | 保持抓握 | 手被锁在世界坐标上，不再跟随真手 |
| 抓取中张开 | 松开 | 立即脱离，恢复到"跟随真手" |
| **收手（手靠近黄点）** | 拉起身体 | 手抓着岩点时，把手往身体方向收，身体就会被拉向岩点 |

**判定细节**：手的"开/合"由指尖到掌心的平均距离比判断，中间有一段"不变"的缓冲带（防止抖动导致反复抓放）。抓取是否成功完全由游戏判断，屏幕上会用颜色和音效告诉你结果。

### 3.2 键盘

| 按键 | 作用 |
|---|---|
| `空格` | 开始 / 继续 |
| `N` | 过关结算后进入下一关 |
| `C` | 重新对齐输入基准（换站位/手部错位时按一下） |
| `R` | **回到上一个检查点**（不限次数，随时可用） |
| `1`–`5` | 直接进入对应关卡（标题页也有选关按钮） |

> 从标题页进入**教学关**或**路段**时默认走**摄像头模式**：没开摄像头会先申请权限；如果摄像头不可用，错误页的"用演示模式继续"会接着进入你刚才选的那一关/那一段。
| `P` / `Esc` | 暂停菜单（继续 / 重新开始本关 / 返回选关） |
| `F` | 显示或隐藏左下角摄像头小窗 |
| `0` | 静音（演示模式里 M 是右手抓握） |

### 3.3 辅助模式（摄像头不可用时的演示/测试通道）

摄像头失败、或者你想在没有摄像头的地方测关卡时，游戏会提示进入**辅助模式**：

| 输入 | 作用 |
|---|---|
| `W` `A` `S` `D` | 移动**手 1**（左） |
| `I` `J` `K` `L` | 移动**手 2**（右；I 上 / K 下 / J 左 / L 右） |
| `X` | 切换手 1 的抓握状态（合 ↔ 开） |
| `M` | 切换手 2 的抓握状态（合 ↔ 开） |

> 抓住以后，**手往哪个方向按，核心就往相反方向走**（相当于把自己拉过去）：手 1 按 `D` 往右，身体就往左；按 `W` 往上，身体就往下。

辅助模式是**功能对等的替代输入**，不是"跳过玩法"：抓取判定、臂展限制、惯性、加速区都和摄像头模式完全一样。它同时也是测试和同伴试玩时的兜底手段。

## 4. 游戏规则

### 4.1 目标

从每张地图的起点出发，**爬到顶部的登顶石**并触碰它，即完成本关。5 关全部完成即通关整个游戏（v0.1.1 只有第 1 关）。

### 4.2 攀岩者由三个点组成

| 部位 | 对应你的 | 物理属性 |
|---|---|---|
| **核心** | 画面正中的黄点 | 有碰撞箱、**有质量**；松手后会下落；抓住时位置严格由手决定 |
| **手 1** | 左手 | 无碰撞箱、无质量、不固定；有判定范围 |
| **手 2** | 右手 | 同上 |

三者的相对位置和你真实身体**严格对应**：抓住东西时，核心就是画面正中的黄点，手相对黄点的偏移 = 手相对核心的偏移（只在被碰撞箱挡住时会有偏差）；松手后核心恢复质量，会带着速度下落。

**黄点 = 身体参照**：画面正中有一个黄点，核心就落在黄点上（镜头永远把核心摆在黄点处）；手的位置是**相对黄点**的偏移，这就是"手相对核心"的位置关系。手离黄点越远，手臂伸得越长。

**臂展极限**：核心到每只手的距离有上限（大约相当于一臂长）。抓得越远、身体偏得越厉害，约束就越紧。

**手部判定圈**：每只手外面有一圈**实线黄圈（42px）**，它就是**真正能抓到的距离**——判定范围和看到的圈完全一样，不多不少。

颜色规则：未抓时圈是**黄色**，抓成功时**只有圈变成绿色**，手形本身不变色；抓空时判定圈会红闪一下。当判定圈内有可抓物时，物体表面会出现一个**绿色小菱形**，告诉你"这里能抓"。

### 4.3 抓取与松开

一次抓取要同时满足三件事：

1. 手是张开的（准备状态）；
2. 这只手离目标物的"抓取范围"足够近；
3. 这一帧你把拳头握上（开 → 合）。

满足就**把这只手固定在当前世界坐标**（之后无论你的真手怎么动，游戏里的手都在那个位置），并记录抓在什么物体上。抓着的时候再张开手掌就松开。

抓住之后，核心的位置就被这只手"钉"住：**核心 = 抓点 − 手相对黄点的偏移**。所以你把手往黄点收，身体就精确地朝抓点移动；把手移开，身体就跟着远离抓点。两只手同时抓时，取两个位置的中间值。

平台上不去时不要硬拉：把手往平台**外侧**带，让身体绕过边缘升到台面以上，再横着挪到平台上方松手。核心不会"瞬移上台面"——碰撞箱只负责把核心挡回去，挡回去的方向永远是"你来的那一侧"。

### 4.4 两种核心策略

| 策略 | 怎么做 | 什么时候用 |
|---|---|---|
| **单手拉起** | 一只手抓住上面的点，把这只手往黄点收，身体被精确拉到抓点附近 | 常规爬法 |
| **交替前进** | 一只手固定 → 另一只手够下一个点 → 换手 → 跟上 | 连续上爬、跨小段空隙 |
| **松手甩出（惯性）** | 快速拉动身体时松手，核心会带着速度飞出去；松手瞬间速度再放大 1.6 倍 | 跨越空隙、冲向更高的抓点 |

核心没有质量和惯性，所以没有"甩起来荡过去"的物理；爬升完全靠"抓点 + 收手"的几何关系。

### 4.5 没有失败

**本游戏没有失败判定，也没有生命值。** 地图四周都有边界（底部是地面，两侧和顶部是岩壁），核心撞上去会停住，**不会掉出世界，也不会弹 "Game Over"**。

松手后核心会**带着最后的速度下落**（有质量）；掉到地面后地面不可抓，只能按 `R` 回到上一个检查点。
- **丢手保护**：摄像头检测不到某只手时，这只手会默认保持"抓紧"状态，不会因为识别丢失而脱手。

### 4.6 检查点与 R 键

- 每关沿路线放置 2–4 个检查点（发光圆环 + 小旗），**一律建在平台顶面上**：圆环立在平台中央，不会悬空。
- 核心穿过圆环即激活，已激活的常亮；HUD 显示 `检查点 2/3`。
- **起点自动算作第 0 个检查点**（也在地面平台上），所以按 `R` 永远不会无路可走。
- 按 `R` 的瞬间：画面快速淡出 → 双手松开 → 传送到最近激活的检查点平台上方 → 速度清零 → 继续爬。
- `R` 不限次数、不扣分、不影响结果记录（计时继续走，只作展示）。
- 想从整关开头重来：`Esc` 菜单 → "重新开始本关"。

### 4.7 通关

核心碰到登顶石的判定圈（半径约 55 像素）即完成：

- 屏幕显示本关用时、检查点复位次数、历史最佳；
- 按 `空格` 重玩本关（暂只有 1 关；第 2–5 关开放后按 `N` 进入下一关）；
- 5 关全部完成后会显示总览——这部分在 v0.2.0 实现。

已通关的关卡和最好成绩保存在浏览器本地（`localStorage`），关掉再打开还在。

## 5. 场景里的五种实体

| 实体 | 有碰撞箱 | 固定 | 有抓取范围 | 玩法作用 |
|---|---|---|---|---|
| **石块** | 有 | 是 | 有 | 最基础的岩点；可抓、可撞、可以站上去 |
| **平台** | 有 | 是 | 有 | 横向长条，容错高；可以站在上面休息，也可以抓边缘 |
| **加速区块** | 无 | 是 | 无 | 透明金色箭头区域；核心进入后获得一个沿箭头方向的加速度（在区域内持续加速，有速度上限）。踩/穿过去会被"甩"出去 |
| **绳索** | 无 | 是 | 有 | 由许多紧密相连的固定节点组成的一条软绳；每个节点都能抓，抓上去会像钟摆一样荡 |
| **登顶石** | 有 | 是 | 有 | 每关终点的发光石头，碰到就过关 |

视觉上：石块偏冷灰、平台带纹理、加速区块是半透明金色带流动箭头、绳索是暖色细线、登顶石会脉动发光。被抓中的点会高亮成金色描边，松手恢复。

## 8. 校准与识别

- **不需要校准**：手的偏移直接按"相对画面中心（黄点）"计算，站好、把双手放进画面就能开始。
- 站得太近/太远、只露一只手、背光严重时，画面里的手会抖或不动，调整位置即可。
- 如果手和身体的相对关系突然错位（比如你换了站位），按 `C` 重新对齐基准。
- 识别状态：正常时小窗边缘是绿色；丢一只手变黄；两只手都丢变红，并在屏幕中央提示"把手放回画面"。
- **不做头部识别**：v0.1.4 起放弃头部追踪，改用**摄像头小窗正中的黄点**作为身体参照——手在哪里、离黄点多远，直接决定手相对核心的位置与手臂长度。
- 黄点画在摄像头画面中央，并向每只手画一条连线（握合时变绿），方便你把手摆到想要的位置。
- 摄像头小窗左上角显示当前识别到的手数（`手 2` / `手 1` / `手 -`）。
- 模型加载失败（断网/被墙）时，会直接给出错误说明并允许切到演示模式。

## 9. 摄像头打不开怎么办

| 现象 | 处理 |
|---|---|
| 双击 `index.html` 后没有权限弹窗、直接报错 | 浏览器把 `file://` 当成不安全来源。**方案 A**：换 Firefox 打开同一文件（它对本地文件的摄像头策略更宽松）。**方案 B**：在项目目录执行 `python -m http.server 8000`，然后访问 `http://localhost:8000`（localhost 一定允许摄像头）。 |
| 权限弹窗被我点了"阻止" | 点地址栏左侧的摄像头图标 → 允许 → 刷新 |
| 摄像头被别的软件占用 | 关掉会议软件/相机应用后重试 |
| 完全没有摄像头 | 进入辅助模式（见 3.3），全部关卡和规则照样可玩 |

> 主入口始终是**双击 `index.html`**。上面两种方案只是浏览器权限受限时的兜底，不需要安装任何东西（方案 B 需要机器上有 Python）。

## 10. 常见问题

**Q：识别的手一直抖，抓不住怎么办？**
A：把手放到画面中更靠中间的位置；避免手和深色衣服重叠；确认光线正面。游戏对"开/合"有缓冲带，轻微的抖动不会误触发。

**Q：只能识别到一只手？**
A：让两只手分开、不要互相遮挡，也不要同时贴在胸前重叠。游戏在只识别到一只手时会保留另一只手的最后位置并提示你。

**Q：手移出画面会怎样？**
A：那只手会停在画面边缘，不会突然抓空导致摔落；屏幕中央会提示把手放回来。

**Q：为什么我抓住了，身体却没往上走？**
A：抓住后核心被"钉"在 `抓点 − 手相对黄点的偏移` 上（抓着时重力不参与）。要往上走，必须**收手**：把手往画面中心的黄点方向收，核心就会朝抓点移动；把手往外伸，核心就远离抓点。

**Q：松手以后会掉，那"严格映射"还算数吗？**
A：算数。抓着东西时核心的位置被严格钉在 `抓点 − 手相对黄点的偏移` 上，重力不参与；一旦松手，核心就恢复质量，带着松手瞬间的速度下落，直到再抓住什么或落地。

**Q：可以两只手同时抓吗？**
A：可以。两只手都固定时核心被吊在中间，适合休息和调整姿势。

**Q：掉回最底下、或者把自己卡住了怎么办？**
A：按 `R` 回到上一个检查点（起点也算一个检查点），不限次数。要是连检查点都救不了，按 `Esc` → "重新开始本关"。

**Q：按 R 会扣分或算作失败吗？**
A：不会。本游戏**没有失败判定**，`R` 只是"回到最近的检查点"，不计惩罚、不看次数。

**Q：窗口缩放/全屏会乱吗？**
A：不会。游戏按 16:9 等比缩放并留黑边，物理和判定坐标不变。

## 13. 已知限制

- 当前只有第 1 关可玩；第 2–5 关的关卡数据还没做。
- **摄像头模式没有在真实摄像头上验证过**（开发环境没有浏览器），识别链路、镜像是按 MediaPipe 文档写的，第一次跑可能需要在真机上微调阈值和映射比例。
- 现在的输入只有手部识别（一个模型），不再依赖面部/身体模型。
- 摄像头依赖联网加载 MediaPipe（jsDelivr + Google 模型仓库）；这两处都访问不了时只能用演示模式。
- 手部遮挡、极快移动时识别会丢帧，表现为手"卡"一下。
- 数值（臂展、抓取容差、摄像头比例）都是先验估计，尤其是"手到身体的映射比例"需要真人试玩后调，调整会记入 [test.md](test.md)。
- 抓着东西时核心是运动学的（为了保证严格映射），所以"抓住时"没有重力；松手才有重量。快速收手再松手，可以带一点甩出去的惯性。
- 检查点的位置和数量是按"路线分段"推出来的，没有经过真人试玩验证，可能需要挪位或增减。
